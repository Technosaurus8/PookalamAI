# Pookalam.ai

A solo freehand pookalam-drawing game with AI judging and a shared leaderboard — built for **ONAM.exe**, the IEEE SB VJCET Online Onam Game-Building Competition.

Draw a pookalam by hand on a digital canvas, get scored by Gemini AI on symmetry, color harmony, and creativity, and see how you rank against everyone else.

🔗 Live app: pookalamai.web.app

## Features

- **Freehand drawing canvas** — smooth quadratic Bezier strokes, Onam-themed color palette, adjustable brush sizes, eraser, undo/clear
- **AI-powered judging** — each submission is scored 0–100 with a short comment, generated by Gemini and returned instantly
- **Live leaderboard** — dense ranking with tie-breaking, rank badges, tap any entry to see the drawing and score in detail

draw, submit, and see your rank in seconds

## 🛠️ Tech Stack

- **Framework:** Flutter Web
- **Canvas:** `CustomPainter` + `Listener` (raw pointer events) for freehand drawing
- **Database:** Firebase Firestore (read-only from the client — all writes go through a secure backend)
- **Fonts:** Baloo 2 + Inter via `google_fonts`
- **Color picker:** `flutter_colorpicker`
- **Image processing:** `image` package (512×512 JPEG export/compression)

## 🏗️ Architecture

This app is intentionally **read-only** against Firestore. Drawings are exported client-side, compressed to a 512×512 JPEG, and sent to a companion [Cloudflare Worker](https://github.com/Technosaurus8/pookalam-worker) which handles AI scoring and the actual database write via a service account. This keeps the Gemini API key and all write access off the client entirely.

```
Flutter Web (this repo)
   │  draws & exports image
   ▼
Cloudflare Worker (backend repo)
   │  scores with Gemini, validates, writes
   ▼
Firebase Firestore
   │  read-only for Flutter client. data is written to the leaderboard collection by the Worker
   ▼
Leaderboard (this repo)
```

See the [Worker repo](https://github.com/Technosaurus8/pookalam-worker) for the scoring/backend implementation.


## 🔒 Security Notes

- The Flutter client has **no write access** to Firestore — all writes happen server-side via the Worker using a service account.
- Firestore security rules are locked to `allow read: if true; allow write: if false`.
- No API keys are bundled in this client.
